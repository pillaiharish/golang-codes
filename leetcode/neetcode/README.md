# NeetCode 150 — independent Go practice starters

[LeetCode library](../README.md) · [0-concepts](0-concepts/README.md) · [Numeric index](INDEX-BY-NUMBER.md) · [Attempt log](REVISION-LOG.md)

**150 unsolved problems, 18 source categories, 24 building-block lessons.** This is a separate practice track: existing solved problem folders elsewhere in the repository are preserved. Every problem has a README and a standalone main.go; there are no algorithm solutions in the problem starters.

## Start here

1. Choose a problem below and read its original summary and official statement link.
2. Follow its ordered prerequisite links inside `0-concepts`.
3. From that problem folder run `go run main.go` on a Mac with Go 1.22+ installed. The starter prints TODO intentionally.
4. Implement the judge-code section, rerun its fixture, and add your own correctness checks. Inspect pointer outputs structurally rather than comparing addresses.
5. Fill the seven-part reasoning worksheet yourself and record an actual attempt. Nothing is marked solved merely because it compiles.

Each folder is a separate `package main`; no root module or shared dependency is required. This also avoids collisions between the many `Constructor` functions. Local node definitions and fixture helpers replace judge infrastructure; submit only the completed judge code and its required imports.

## Source and access notes

Membership and category order come from [NeetCode's official metadata](https://github.com/neetcode-gh/leetcode/blob/main/.problemSiteData.json), selecting `neetcode150: true`, checked 2026-10-20. [manifest.json](manifest.json) records all 150 IDs, source links, prerequisites, and a hash of the membership source. Titles, public constraints, example data, and 143 Go interfaces were checked against LeetCode's public question endpoint.

Statements are original summaries with factual input/output details, not verbatim reproductions. Diagrams, full wording, and any additional clarification remain on the official question pages. Seven premium questions (#252, #253, #261, #269, #271, #286, #323) do not expose their statements or Go starters publicly. Their README files explicitly flag adapted local interfaces and unavailable bounds rather than inventing them. Verify those interfaces with authorized access before submission.

## Verify this practice track

```sh
python3 leetcode/neetcode/verify.py
```

Run from the repository root. The verifier checks the manifest, 150 folders, Markdown navigation, Go compilation, and all local entry points; it also runs the 24 concept programs. It does **not** certify your algorithms or count TODO messages as solutions. Run each `main.go` directly when working on a problem. The verifier uses only Python's standard library and the Go toolchain.
