In practice top-end Go devs mix the two:

jobs ───▶  workers  ───▶ results
              │            ▲
              └─ wg.Done() │


jobs channel → distributes work (fan-out)

each worker pushes its answer on results

a WaitGroup tracks when all workers have called Done(); once wg.Wait() returns we close results so the collector knows no more data is coming.
This “fan-out / fan-in” loop is the first bigger pattern in the Udemy course.
